## Not yet covered

- **Not embedded in artifacts.** The analysis model still carries its own provenance block (`ProvenanceModel`). Nothing writes a `ProvenanceRecord` into an artifact yet. Adopting it is a schema change for each artifact, and each needs its own bump.
- **Build identifier is not set by any build.** Nothing in the repository sets `ECTT_BUILD_ID`. Until a build does, every record reports `unset`. This is honest but weak evidence of which build made an artifact.
- **Dependency versions are the caller's job.** No code yet collects libclang's version into a record. The analysis layer already has `get_libclang_version`. Wiring it in belongs to the caller.
- **No check that the record reproduces the artifact.** TOOL-QUA-060 asks for sufficient information. Whether that information is enough to rebuild the same bytes needs a replay test, which does not exist yet.

## Design notes

- **Why the timestamp is outside the hash.** A timestamp in the hash would make two identical productions produce different digests, so a digest could never prove a match. Keeping it beside the digest keeps the timestamp available without weakening the proof.
- **Why no source-tree version fallback.** The source constant is what the tree says, not what is installed. Reporting it as the installed version would make a stale checkout look current.
