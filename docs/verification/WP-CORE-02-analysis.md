## Design notes

- **Why a subclass root, not a rename.** `CoreError` keeps its name and signature, and is now a subclass of `EcttError`. Every existing `except CoreError` and `isinstance` check still works, and no test needed editing.
- **Why categories live on package bases.** A category is per package family and is inherited. Putting it on each leaf class would be redundant and easy to get wrong.
- **Root initialisation is not output.** The marker file and `.gitignore` are created before a transaction opens and survive rollback. Otherwise a cancelled first run would leave the root in a state the next run would reject.
- **Directory cleanup is conservative.** Only directories the scope created are removed, and only when empty.
- **Exit codes: adopt, do not extend.** The WP-CLI-02 table is a stable contract (TOOL-CIC-030) frozen by an existing test, so every error category maps to `EXIT_TOOL_ERROR` and the category/reason stay visible on stderr via `EcttError.__str__`. A dedicated interruption code would require an owner release-note entry and is recorded in SECOND_PASS as an option, not decided here.
- **Totality over the mapping.** `exit_code_for_category` defaults unknown categories to `EXIT_TOOL_ERROR` (fail-safe), and `test_mapping_is_total_over_discovered_error_classes` walks the whole package tree so a future category cannot silently bypass the table.
- **The adopted operation is the pipeline harness.** Within this item's allowed paths the only existing long-running multi-write operation is the fixture pipeline used for reproducibility verification; routing it exercises the fail-safe guarantee end-to-end (cancellation and injected failure) without touching lane-owned packages. Product operations follow in their own work packages.
